# 情感正文多轮对话改单轮对话实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将飞书“情感 IP”子表中多轮对话文案整理为“用户：一次性描述情况 / 主播：一次性解答”的短视频脚本格式。

**Architecture:** 复用项目现有 `scripts/feishu_utils.py` 的飞书鉴权、表格读取和按列写回能力。先读取“文案全文”列并按说话人标签解析；根据每段内容判断“用户”或“主播”，分别按原始顺序合并，最后只更新“文案全文”字段，保留其他字段和行号不变。

**Tech Stack:** Python 3、项目现有飞书 Sheets HTTP API 封装、正则文本解析、人工抽样复核。

## Global Constraints

- 目标子表：`情感 IP`，sheet id 为 `sy4S58`。
- 目标字段：仅修改 `文案全文`；不修改采集 id、分类、标题、平台、链接、数据指标和审核字段。
- 当前读取结果：291 条数据，其中 131 条含“说话人”标签，160 条已是无标签单段口播。
- 本轮先只生成预览和计划；未经确认不得向飞书写入。
- 无说话人标签的 160 条先保持原文，不强行添加“用户/主播”标签。
- 合并以保留原文信息为主，不主动重写观点、增删事实或改变情绪走向；只做标签替换、分组、换行和必要的空白清理。

### Task 2: 确定角色归并规则

**Files:**
- Create: `scripts/transform_emotion_dialogue.py`（执行阶段创建）
- Test/Preview: 项目临时预览输出，不写回飞书

**Interfaces:**
- Consumes: 单条含标签的原文，例如 `【说话人1】：...\\n【说话人2】：...`。
- Produces: `{用户: str, 主播: str, status: str, reason: str}`，供预览和写回阶段使用。

- [ ] 解析所有 `【说话人N】：` 段落，保留每段在原文中的顺序和正文。
- [ ] 识别主播段：主播自称、主持/引导开场、向对方追问、对案例作判断/建议、对直播间观众说话、承诺帮助或作结号召等内容归入“主播”。
- [ ] 识别用户段：个人年龄、地域、家庭经历、当事人诉求、回答主播问题、表达困惑或感谢等内容归入“用户”。
- [ ] 对三人及以上样本，不按数字标签判断；将主播相关段合并到“主播”，将来电者/当事人相关段合并到“用户”。例如部分样本是“说话人1=主播开场、说话人3=用户、说话人2=主播回复”。
- [ ] 对多个来电者或现场第三方无法可靠归类的行标记为 `需人工复核`，不自动写回；避免把不同人的内容误并成同一个用户。
- [ ] 对角色边界明确但标签交错的行，将所有用户段按原始出现顺序拼为一段，将所有主播段按原始出现顺序拼为一段；输出顺序固定为“用户”在前、“主播”在后。
- [ ] 仅删除原有 `【说话人N】：` 标签和多余空白；不删除用户叙事或主播解答内容，不擅自补写内容。
